# IP适配与脚本

让参考材料回答“这次可以学哪一点”，让本IP资料回答“这句话由谁来说、凭什么说”。产出能交给自动分镜的稿件及来源对应关系。

## 接收当前任务

读取本轮目标、用户已指定的题目/授权、当前IP资料、拆片卡和可复用做法。先核对主体，不把用户本人、团队客户和外部博主混成一个人。沿用正在使用的项目目录；独立任务放在用户指定工作目录的 `<IP>/<日期_项目>/`。未指定工作目录时先询问保存位置；不知道 IP 时先用任务名，不替用户命名身份。

IP资料至少需要受众与本次问题、可用事实/方法、表达样本、出镜与素材条件。已有资料足够就写；缺某个客户结果时只停止写该结果，继续基于已知材料起稿。确实缺少主体或题目范围时集中问必要问题，不启动完整定位访谈。模板见 [IP资料与适配表](assets/IP资料与适配表.md)。

## 从参考到自己的稿

1. **登记证据。** 打开实际要使用的原材料，建立来源ID。区分本IP确认事实、第三方事实/观察、方法资料、创作建议与教学设定。引用第三方经历保留第三方归属；一句引用和一项生成建议分别标记。只有标题或摘要时不声称已经读过原文。
2. **逐项判断采用/改造/不采用。** 写清参考作品+原片位置、表达问题、本IP为什么适合、自己怎样说/怎样拍、所需资源与缺口。采用的是可描述的做法；外部作品的人物身份、案例结果、专属措辞不得自动迁移。若只有文字拆解，就只引用文字层观察。
3. **选题。** 用户已指定题目就进入该题。需要候选时默认给3个，每题写受众问题、核心表达、本IP依据、参考做法、拍摄可行性。用户授权“直接出1.0/你来选”时可选最有依据的一题，记录选择理由，不重复求确认；仅让给候选则停在候选，不自行写全文。
4. **起稿。** 用该IP确认的表达样本控制口吻；缺样本采用自然中性表达并标记暂定。开头承诺由正文兑现，正文围绕一个具体问题，每段落到可说的句子。用户要求小幅修改时按其幅度与原结构保留。要分类钩子/刺点时读取本批拆片所用、使用者有权使用的“13类钩子+6类行为刺点”定义，不另起分类；定义未提供时先保留原句与观察，不猜测标签。
5. **核对。** 检查主体、数字、时间、案例、引语与来源一致；当前医疗/财税等具体专业结论按该领域需求核验，不把其他行业表达边界套来。没有相应依据就去掉该事实，或在交接说明列缺口，不能把“待补”当作可直接说的口播事实。
6. **交接。** 输出下列文件。将每段口播原文保存在 JSON 的 `segments`，参考来源另放 `source_refs`。分镜时保留这些文本，不默默再改稿；修改稿版本变化时重新校验分镜覆盖。

## 交付与状态

- `script/script.md`：标题、口播正文、版本；给拍摄者的正文不夹操作指令。
- `script/adaptation.md`：适配表、实际读取范围、选题依据、来源登记、缺口、稿件状态。可复制上述模板。
- `script/script.json`：机器可读的分段稿和来源表，按 [交接格式](references/script-contract.md)。

状态写 `draft` 或 `ready_for_storyboard`。后者只代表事实核对范围内可做分镜，**不等于用户批准或已发布**；若用户要求先审稿，则停在 `draft`。需要候选、不写稿时只交付适配文件，记录 `candidates_only`，不制造空的脚本成品。

需要分镜时可把上述产物交给 `$ip-auto-storyboard`；本技能单独调用也能交付可读稿件。生成脚本不触发转写收费、知识库批量改写、消息发送或发布。
