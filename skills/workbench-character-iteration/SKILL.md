# 工作台角色视觉迭代

把“差异大一点”“更抽象”“更立体”“有科技感”“喜欢第三种”等反馈落实到同一组角色的连续修改中。让下一轮沿着用户选中的方向推进，并能找回参考、版本和选择依据。

## 使用方式与范围

- 用户只要求整理反馈、总结流程或制作提示词时，交付相应文字；只有要求生成或修改图片时才实际出图。
- 用户要求继续设计时，从已知材料直接开始；仅在基准图、指代或关键约束无法确定时询问。无需每轮重新做完整访谈。
- 复用本项目现有角色、名称、岗位和图像工具。一次项目中的七个角色、三套方案、金属材质或偏爱第三种，都不是其他项目的固定要求。

## 基础配置

提供基准图片、角色清单、本轮反馈、目标尺寸和输出目录。实际出图需要支持参考图编辑的图像工具；本技能不附带图像服务、额度或历史角色素材。用户指定工具时使用指定工具；工具不可用时仅交付已完成的文字或方案，并明确图片尚未生成。

调用示例：`使用 $workbench-character-iteration，基于第四轮第三张，只增强颜色饱和度，保留轮廓、表情和材质，先给预览。`

## 先确定基准与本轮变化

读取用户当前指定的图片、反馈和已有版本记录。编辑本地图片前查看原图；只有摘要或“已生成图像”按钮时，不能据此描述实际造型。

用已有信息确认：角色用于哪里（侧栏头像、会话头像、角色展示板等）、角色清单、当前基准文件、本轮目标以及明确不变的内容。若用户只改头像，不扩展到工作台布局、Logo、岗位命名或业务功能。

实际执行图像迭代时，每轮保留一条简短记录，存入项目的迭代说明；小任务直接在现有记录中追加即可。仅分析或总结时在回复中整理，除非用户要求保存：

```text
轮次 / 方案 ID：R04-C03
基准图：具体路径或附件；不能只写“第三张”
反馈原文及来源：用户消息 / 已提交历史消息 / 输入框草稿 / 助手建议
保留：本轮已认可的身份、轮廓、五官、表情、岗位关系、其他固定要素
调整：本轮要改的具体视觉变量
待确定：只列影响本轮实施的缺口
产物：版本路径；目标尺寸；实际像素；格式与透明通道
状态：预览 / 已选方向 / 独立资产已生成 / 已接入 / 接入已验证
```

当前明确指令优先。历史输入草稿只能作为候选意图，不能记为已确认要求；助手对方案的描述也不能冒充用户偏好。用户说“可以的，再……”通常意味着继续保留上一轮已认可部分，不从头重设计。

## 把反馈变成可见的改动

下面是解释反馈的可选设计手段，按当前参考选用，不把所有手段同时堆到一张图里。

| 用户反馈 | 主要调整 | 保持与检查 |
|---|---|---|
| 角色差异不够、都像同一个 | 调整轮廓、比例、重心、五官位置、表情或姿态，形成单独辨识点 | 保持同一团队的视觉语言；缩小后仍能区分，不能只换颜色和配件 |
| 更抽象 | 用非具象形体、不规则比例、错位五官或简洁表情表达性格 | 以参考与反馈解释“抽象”；不要未经要求改成一组动物或每人一个职业道具 |
| 更立体 | 增强厚度、体块转折、遮挡、接触阴影与光照层次 | 已认可的轮廓、五官与表情保持可识别，避免整组角色重新变成同款圆头 |
| 更有科技感 | 用材质反光、局部金属、半透明表面或少量灯光等形成方向差异 | 科技感不等于统一机器人、全屏霓虹或复杂背景；以角色本身为重点 |
| 颜色稍微饱和一些 | 在已选角色与配色关系上适度增加色彩饱和度 | 保留材质、明暗和角色区分，不顺带大改形体；没有实测参数时不编造提升百分比 |
| 喜欢第三种 / 就按这个 | 将本轮第三个方案的实际文件设为后续基准 | 喜好确认只确认方向；是否制作资产或接入页面，依照本次任务已有授权 |

只改本轮要求的维度；必要的联动改动简短说明。若同时收到相互冲突的要求，只询问冲突部分，继续整理已明确部分。

## 生成与比较

1. 先把基准和变化写成明确的生成或编辑指令。使用用户指定工具；未指定时，实际生成或编辑图片按当前可用的 `imagegen` 技能及工具执行。工具不可用时说明卡点并保留提示词，不声称已经出图。
2. 编辑要传入准确参考图，不能只靠一段旧描述重新生成。保留原版，新结果使用新版本文件名；单点修改通常给一个修订版即可。用户需要探索时再给少量有明确区别的备选，不强制每轮三套。
3. 各候选使用稳定的“轮次＋方案”ID、短名称与独立文件。按真实展示顺序列出映射，避免把工具统一的“已生成图像 1”标签当成业务编号。失败或缺图仍保留原 ID，不让剩余方案自动顶替编号。
4. 尽量统一比较视角、画布和背景。重点看角色时单独展示角色，避免界面装饰掩盖差异；展示板中的小头像示意不能写成真实界面验收。
5. 展示当前轮次的图片及一句差异说明；需要用户选方向时，只问影响下一轮的一个问题。已有清楚的选版与修改指令就直接继续。

可用的编辑提示结构：

```text
基于所附的 {轮次-方案 ID / 基准图} 编辑，用于 {实际位置}。
保留 {已认可的角色身份、轮廓、五官、表情、材质、布局等}。
本轮仅调整 {用户反馈对应的可见变化}，幅度为 {轻微/中等/明确描述}。
角色数量与对应关系为 {当前清单}；不增加或遗漏角色。
背景与透明要求为 {当前要求}；保持 {宽高比}，目标 {实际像素规格}。
{仅加入本轮确实需要排除的偏差}。
```

## 选版后制作与核验

- 选中某套后，锁定确切基准并沿它修改；不要再混入未选方案的身份特征。需要独立头像或 Logo 时分别制作，不把一整张概念板当成已交付的独立素材，也不粗切角色边缘。
- 默认图片长边目标 2048 像素并保持原比例；16:9 示例为 2048 × 1152，方形为 2048 × 2048。当前用户指定的尺寸优先。对内置 image_gen 在提示词中写明目标，不虚构尺寸参数。
- 每次实际生成或编辑后读取最终文件像素，例如 macOS 用 `sips -g pixelWidth -g pixelHeight '/absolute/path/image.png'`。需透明背景时核验 alpha 和实际边缘，不能仅凭 PNG 后缀判断。
- 若实际像素未达目标，标明实际尺寸与工具限制，说明本轮可交付到哪一步；不默默换模型、付费接口或插值放大。后续放大需按用户决定执行并标为放大结果。
- 观察角色是否遗漏、串位，轮廓和小表情是否漂移，材质或饱和度是否落实，边缘是否裁切。需要 UI 使用时按实际头像显示尺寸检查，而非仅在大图看细节。
- 用户要求接入工作台且已有具体授权时，继续完成并验证，不重复询问。先读目标项目规则与现状，只修改约定的视觉资产和映射，保留岗位 ID、聊天数据、业务功能和未授权改动。核验实际目标页面中的加载、身份对应、尺寸与完整轮廓。

## 交付

先展示本轮图片或交付物，再简要说明“基于哪一版、改了什么、实际尺寸、当前状态”，给出可打开的版本文件。生成工具已在聊天中展示图片时，避免重复贴同一张。

明确区分方向选择、独立素材产出、页面接入和实际验收。只完成视觉预览时不声称已接入；只要求整理反馈时不额外生成图片、开发页面或创建后台任务。

新增设计产物保存在用户指定的输出目录。沿用已有项目时保留原目录结构；独立项目可按 `<输出目录>/<项目名>/<轮次>/` 组织，每轮保留基准图、结果图和简短迭代记录。
