# 自动分镜与拍摄清单

把“说什么”变成“这句话拍什么、哪里切、要准备什么”。本技能由当前AI进行分镜编排，附带的本地脚本只校验与排表，不是视觉理解或生成视频服务。

## 接收与边界

优先读取现有 `script/script.json`、`script.md`、适配表、拍摄条件和已拆片的真实参考；用户只给普通文稿时按 [分镜数据格式](references/storyboard-contract.md) 先建立分段稿，原文不改。不要强制先运行其他技能。已明确要分镜就是当前授权，不重复让用户选题/批准。

确认当前主体、版本、比例、时长要求、出镜人数、可用场景/设备/素材。缺场地时先给可执行的中性拍法并列待确认项；缺少一项外部片段只暂停使用该片段，不停止整个稿件。没有画面观察证据时，做法标“本次设计建议”，不说来自真实博主。

## 编排

1. **锁定文本。** 给原稿逐段编号。若当前要求只是分镜，不删字、换说法或为了时长加速硬塞。明显过长时给预计超时和可选压缩建议，改稿只在已有授权内实施，之后更新版本。
2. **按信息变化切镜头。** 一段可以拆成多个镜头，也可以一个镜头承载多个段落。先确保观众听得懂：人物提出问题；实物/录屏展示对象；细节画面指出位置。是否切镜头取决于信息与动作，避免每句机械换画面。
3. **逐镜头写具体动作。** 记录拍摄方向、景别、固定/移动、人物动作、实际画面、叠加文字、切换触发点、声音处理。写“说到‘时间位置’时圈出该字段”，不用“增强高级感”等无法执行的词。画面与对应口播有意义联系，不用无关素材填满。
4. **保留借鉴出处。** 来源ID指向参考作品+原片位置，说明只借哪一项做法及怎么改。主片的新时间从0开始；原片时间留在来源列，严禁混成一个时间轴。
5. **先按条件做得到。** 一人+手机就优先固定机位与自制录屏；需要第二演员、外景、未有授权素材时给当前能拍的替代。未取得的素材列为待拍/待取得/拟生成；不能写成已有。自动分镜不默认为用户购买素材、调用付费转写、生图、配音、渲染或发布。
6. **时间写实。** 无实际口播音频时 `timing_basis=estimated`，逐段按文本、动作、阅读负担估时并标“待实读校准”；不得声称精准卡秒。已取得音频并实际对齐时才使用 `aligned_audio`，记录音频文件、对齐结果及核验位置。原片时长不能直接当新稿时长。
7. **生成并检查。** 按数据格式生成 `storyboard/storyboard.json`，用下方命令检查并渲染 Markdown/CSV。核对每个字符在分镜中按顺序覆盖一次、时间连续、素材编号和参考ID能解析；逐镜的素材编号同时登记画面和声音，口播跨镜延续时仍列出口播源素材；最终人工复核每镜是否讲清内容、能否拍到，校验器不会替你判断这些。

## 运行与交付

Python 3 标准库即可；命令中的路径替换为当前项目。用户指定现有工具时保留该工具流程，本技能产物可作为输入，不重复开发工作台。

```bash
python3 <本技能目录>/scripts/storyboard_tools.py render \
  --script <项目>/script/script.json \
  --board <项目>/storyboard/storyboard.json \
  --out <项目>/storyboard
```

输出 `storyboard.md`、`assets-needed.csv`、`validation.json`。已有同名文件默认拒绝覆盖；确认是本轮自己的中间版本后可加 `--overwrite`，用户已有修改先读并保留。只校验时用 `validate` 替换 `render` 并省略 `--out`。

验收包含：稿件版本一致；口播文字不重不漏；新时间从0连续；每镜头有画面/剪辑/声音/资源；已有与待准备素材分开；实际音频对齐与预计时间分开。输出只有分镜和清单时，明确“尚未拍摄、尚未渲染”。

可复制的教学样例在 [assets/teaching](assets/teaching/)，原片参考为0，均明确标教学自制。按其中输入实际生成一套表即可验证工具；不能作为真实博主拆片成果。
