# 视频拆片

把“这个视频拍得好”变成“第几秒用了什么，为什么可参考，自己需要什么条件才能用”。一条作品对应一张卡；输入原片和已有时码转写，输出 `breakdowns/R01.md`、`breakdowns/R01.json` 及对应证据。

## 先确认手里的素材

- 有已选作品清单时沿用 `source_id`、原链接、作者和排名，不重选热门。独立调用则给作品分配稳定编号。
- 查本次真实本地视频、已有 SRT/时码 JSON、作品链接和输出目录。缺少视频可先做文字层分析，画面与声音保持未知；缺少转写可先看画面。缺口只阻塞依赖它的部分。
- 原片只读。已有转写优先复用；不要为拆片自动重复付费转写、采集其他账号或修改正式知识库。

## 准备证据

优先使用当前项目已经取得的场景切点、截图和转写，核对它们属于同一原片。需要生成时，使用本技能的 [prepare_evidence.py](scripts/prepare_evidence.py)：

```bash
python3 scripts/prepare_evidence.py \
  --media "/绝对路径/原片.mp4" --source-id R01 \
  --transcript "/绝对路径/原片.srt" \
  --out "/项目目录/evidence/R01"
```

脚本复用本机 ffmpeg/ffprobe，生成候选切点、候选画面、转写映射、可打开的截图索引和原片指纹。运行方法、已知限制和工具路径配置见 [preparation.md](references/preparation.md)。脚本不调用模型或云端，不承担语义分析。

**候选切点不等于最终镜头，生成截图不等于看过，存在音轨不等于听过。** 脚本输出的 `coverage.*.reviewed` 全为 false，后续只能按实际查看、播放、阅读的记录更新。

## 按三条线拆

1. **文案线**：读时码转写，保留原文及顺序，写开场承诺、展开、证据、结尾行动。引用原文与分析分开；转写错字在校对字段记录，不改写为博主从未说过的话。钩子、刺点沿用 [taxonomy.md](references/taxonomy.md) 的 13＋6 标准名称；分类须先读取使用者有权使用的定义资料，未提供定义时标签留空，继续其余拆片。
2. **画面线**：逐个候选镜头看原片或截图，补看切换前后及漏检区间。保留 11 字段：镜头号、场景、角度、镜头状态、截图、字幕内容、字幕样式、音效、花字、动画、时长。再写“对应哪句文案”和“画面帮助理解什么”。截图只能证明瞬间构图，运镜、动画时长和转场须回看连续片段。未知字体写可见样式和“具体字体未确认”。
3. **声音线**：使用可听的原片/音频工具，记录实际听到的口播、音乐、音效、进出点与画面关系。没有听取能力或未播放成功则标未知，不能从字幕、波形或音轨信息推断“有鼓点/无配乐”。

按叙事或镜头变化定段，不强制每句话一镜。每段写原片相对秒数及 `MM:SS.mmm` 展示时间，观察事实与效果解释分开。对“为什么吸引人”使用分析判断，不能把高点赞归因为某个手法已获证明。

## 交付和交接

读取 [artifact-contract.md](references/artifact-contract.md)，复制 [breakdown-template.md](assets/breakdown-template.md) 填写 Markdown，同时保存对应 JSON。两份同一版本、同一段落编号，原文和截图仍链接原片。

- `coverage` 写清视频实际连续观察范围、仅截图观察范围、音频听取范围、转写阅读范围及观察者/工具；不能把抽样范围填成全片。
- 每个重要结论带作品编号＋起止时间＋截图或听看记录。可复用点写“借什么／原证据／适用条件／不能照搬什么”，供后续 IP 适配使用。
- `missing` 列出缺原片、未听声音、时码冲突、截图不足、未核实参数等，并说明影响哪项结论。
- 全量视听拆片：每段和全片均有实际画面与声音复核，或证实文件无音轨；只有文字或抽样则交付为部分完成。
- 工作流阶段是 `breakdown`；`status: ready` 仅表示这张完整拆片卡的阶段检查通过，不代表已入正式库、脚本已采用或可以发布。部分完成用 `needs_input`，保留已有结果；下一阶段是 `knowledge`。

交接前核对原片哈希、全部段落时码位于时长内、顺序合理、每项证据可打开、无凭空补齐的镜头/声音、13＋6 名称正确，以及 Markdown 与 JSON 一致。十条批量按条报告，不用一条成功概括全批完成。
