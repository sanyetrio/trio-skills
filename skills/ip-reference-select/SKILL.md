# 热门作品筛选

## 输入与范围

先确认当前账号、作品时间范围、实际采集覆盖、比较指标与目标条数。用户只给链接时先调用当前可用的博主采集技能；已有CSV/飞书记录则直接读本批数据。读取前先检查现有来源说明，不能把采集器设为10条理解成已取得热门前10。

需要至少作品ID、作者、标题、原链接、数据观察日期、同一指标原值。可用播放量按播放量，无播放量但用户接受可见互动指标时按点赞等统一指标，并明确叫“本批已取得作品中按点赞排序”。缺必要指标集中说明，其他作品保留。

## 操作

1. 读取完整本批清单；按 [输入字段](references/input.md) 映射CSV，保存映射依据。英文机器字段仅用于脚本，不要求用户手工转换。
2. 核对重复ID/链接、作者范围、日期与数据。保留原文件；重复版本先查时间与口径，不能随意挑较大值。
3. 使用 `scripts/rank_videos.py` 排序。脚本不联网、不改变原清单，输出到新版本目录。条数按用户本次要求，未指定且任务是本SOP时用10。
4. 回读selection.json和top.csv，处理缺值、显示缩写、边界同分与跨日快照警告。脚本只排序所提供的数据，不证明全账号完整或数据真实。
5. 逐条确认原片与转写可用性，单独记录未取得原片、无声音、无转写的作品；不能悄悄用低排名作品顶替。

```bash
python3 scripts/rank_videos.py --input /任务目录/inputs/作品.csv --out /任务目录/selection/v1 --account 指定作者 --metric likes --count 10 --scope 本次取得作品的实际范围
```

## 交付与验收

- `ranked.csv`是本批所有可排序记录，`top.csv`是入选条目，`excluded.csv`是因数据问题未参加排序的记录；输入总数与后二类数量应能对上。
- `selection.json`保存原文件SHA256、账号、范围、指标、日期、条数、入选完整记录和警告。
- 作品ID作为后续source_id持续使用；热门名次只是rank，不用改名覆盖身份。原片时间、转写路径在后续作品卡补齐。
- 任何缺项或不明确排序仍记partial；只有回源核对完、入选理由成立才可被主SOP记ready。不能由脚本的ready_for_review直接推导已通过人工核对。
- 无法取得10条就交真实条数与缺口，其他独立工作可继续。采集失败的素材保存原任务编号，未知付费转写状态先查原任务。
